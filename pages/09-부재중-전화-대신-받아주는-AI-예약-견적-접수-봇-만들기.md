### 전화를 못 받는 시간이 가장 비싼 시간입니다

정비소, 출장수리, 인테리어, 설비, 1인 샵. 예약을 전화로 받는 가게는 하루에도 몇 번씩 전화를 놓칩니다. 현장에서 손이 젖어 있을 때, 점심을 먹을 때, 문을 닫은 뒤. 고객은 그때 다른 곳에 전화를 걸고, 남는 것은 부재중 표시 하나입니다.

호주에서 이 문제를 팔아 월 매출 6만 3천 호주달러(영상 기준, 약 5,800만 원)를 만든 회사가 있습니다. 예약 위젯 하나였습니다. 영상에 나온 지출은 서버 150, 협업툴 120, 문서도구 130, AI 음성 500, **문자 4,000**, 리드 수집 400, AI 모델 800(모두 달러)입니다. 눈에 띄는 것은 문자비가 가장 크다는 점입니다. 이 사업의 본체가 전화가 아니라 **문자**라는 뜻입니다.

다만 영상 속 숫자는 매출이고 이익이 아닙니다. 직원 3명 인건비와 고객이 내는 요금은 공개되지 않았습니다. 그대로 따라 하면 안 되는 이유는 따로 있습니다.

### 한국에서는 '전화 받기'가 이미 싸졌습니다

통신사가 AI 통화비서를 월 단위로 팝니다. KT AI 통화비서는 라이트 월 5,500원, 스탠다드 월 22,000원(부가세 포함, 2026-11-21 공식 안내 화면 기준)이고 스탠다드에는 예약·주문 접수와 월 300건 무료 문자가 들어 있습니다.

그래서 개인이 "AI가 전화를 받아 줍니다"를 새로 만들어 팔 자리는 거의 없습니다. 남는 자리는 그 다음입니다.

- 통화 내용이 **업종에 맞는 질문 5개**로 정리되는가
- 접수된 건이 **표·캘린더**에 쌓이는가
- 확정과 리마인더 문자가 **자동**으로 나가는가
- 사장님이 **한 화면**에서 오늘 확정 건을 보는가

이 장에서는 이 네 가지를 무료 도구로 직접 만듭니다. 오늘 30분이면 첫 버전이 돌아갑니다.

### 전체 구조는 4단입니다

| 단계 | 고객이 하는 일 | 자동으로 되는 일 |
|---|---|---|
| 1. 감지 | 전화를 걸었다가 끊는다 | 부재중·영업종료 안내 문자가 나간다 |
| 2. 회수 | 문자 속 링크를 누른다 | 질문 5개짜리 폼이 열린다 |
| 3. 정리 | 증상·위치·희망일을 고른다 | 표에 1건 쌓이고 사장님께 알림이 간다 |
| 4. 확정 | 확정 문자를 받는다 | 캘린더에 일정, 전날 리마인더 |

이 중에서 **1단계만 공짜로 안 됩니다.** 부재중을 감지하려면 통신사 부가서비스나 통화비서가 필요합니다. 2~4단계는 무료 도구로 만들 수 있고, 여기까지 만드는 것만으로도 사장님이 아침에 하는 손작업이 사라집니다.

### 30분짜리 최소 구성

가장 빠른 길은 **구글 설문지 + 스프레드시트 + 앱스 스크립트**입니다. 서버도 도메인도 필요 없습니다.

1. 설문지를 만든다. 질문은 5개로 끊는다.
2. 응답을 스프레드시트에 모은다(설문지 화면에서 연결).
3. 스프레드시트에서 `확장 프로그램 -> 앱스 스크립트`를 열고 아래 코드를 붙인다.
4. 트리거를 `스프레드시트 > 양식 제출 시`로 건다(설치형 트리거).
5. 자기 번호로 한 번 제출해 캘린더와 메일이 오는지 본다.

질문 5개는 업종이 정합니다. 많으면 아무도 안 씁니다.

| 순서 | 질문 | 형식 |
|---|---|---|
| 1 | 무엇을 도와드릴까요 | 짧은 답변(한 줄) |
| 2 | 어디에 있으신가요 | 짧은 답변(동 이름 정도) |
| 3 | 언제 방문하면 좋을까요 | 날짜 |
| 4 | 예산 범위는 어느 정도인가요 | 객관식 3개 |
| 5 | 연락받을 번호 | 짧은 답변 |

객관식은 3개면 충분합니다. 선택지가 많으면 고객이 고민하는 동안 창을 닫습니다.

```javascript
function onFormSubmit(e) {
  var v = e.values;                 // [시각, 1번답, 2번답, 3번답, 4번답, 5번답]
  var 시각 = v[0];
  var 요청 = v[1];
  var 위치 = v[2];
  var 희망일 = v[3];
  var 예산 = v[4];
  var 연락처 = v[5];

  var cal = CalendarApp.getDefaultCalendar();
  cal.createEvent('[접수] ' + 요청 + ' / ' + 위치, new Date(희망일), new Date(희망일));

  MailApp.sendEmail({
    to: Session.getActiveUser().getEmail(),
    subject: '[접수] ' + 요청,
    body: '접수 시각: ' + 시각 + '\n위치: ' + 위치 + '\n희망일: ' + 희망일 + '\n예산: ' + 예산 + '\n연락처: ' + 연락처
  });
}
```

이 코드는 캘린더에 하루짜리 일정을 만들고 담당자에게 메일을 보냅니다. **문자를 보내려면 별도 발송 서비스의 API 키가 필요하고, 그건 무료가 아닙니다.** 처음에는 메일로 시작하고, 접수가 실제로 쌓이는 것을 본 뒤 문자를 붙이는 순서가 안전합니다.

### AI에게 맡길 것과 맡기지 말 것

AI가 잘하는 것은 **정리**입니다. 접수 원문을 읽고 급한 건과 아닌 건을 나누고, 답장 초안을 쓰고, 방문 전에 확인할 것을 뽑습니다.

AI에게 맡기면 안 되는 것은 **확정**입니다. 일정 충돌, 예산 초과, 애매한 요청은 사람이 봐야 합니다. 자동 확정을 넣으면 잘못 잡힌 예약 하나가 그날 하루를 망칩니다.

정리용 지시문은 이렇게 씁니다. 접수 표의 한 줄을 붙여 넣고 돌립니다.

```
아래는 매장에 들어온 예약 요청이다.
1) 급한 순서로 3개만 줄을 세우고 이유를 한 줄씩 써라.
2) 방문 전에 확인해야 할 것을 3개 이하로 뽑아라.
3) 고객에게 보낼 답장 초안을 3문장으로 써라. 확정이라는 단어는 쓰지 말고 "확인 후 연락드린다"로 끝내라.
원문에 없는 내용은 만들지 말고, 비어 있으면 "확인 필요"로 표시하라.

원문:
(접수 표의 한 줄)
```

마지막 두 줄이 핵심입니다. 이 문장이 없으면 AI는 없는 방문 시간을 만들어 냅니다.

### 비용은 얼마인가

| 항목 | 단가 예시(부가세 별도) | 확인일 |
|---|---|---|
| 알림톡 1건 | 6.4원 ~ 13원 | 2026-11-21 |
| 문자(SMS) 1건 | 7.9원 ~ 18원 | 2026-11-21 |
| 문자(LMS, 장문) 1건 | 24.5원 ~ 45원 | 2026-11-21 |
| 설문지·스프레드시트·캘린더 | 무료(계정 할당량 내) | 2026-11-21 |

월 300건이면 문자로 2,400~5,400원, 알림톡으로 1,900~3,900원입니다. 알림톡은 정보성 문구만 되고 템플릿 사전 심사가 있으니, 심사 전에는 문자로 시작하십시오.

단가는 발송 서비스마다 다르고 자주 바뀝니다. 계약 전에 그 서비스의 요금표를 열어 확인하고, 확인한 날짜를 메모해 두십시오.

### 조용히 무너지는 곳 네 군데

**첫째, 개인정보입니다.** 이름·연락처·주소는 개인정보입니다. 받는 항목을 최소로 줄이고, 보관 기간과 파기 방법을 정해 두십시오. "언젠가 지운다"는 없는 것과 같습니다. 설문지 응답이 쌓인 계정의 접근 권한도 정리해야 합니다.

**둘째, 광고성 문자입니다.** 예약 안내는 정보성이라 수신 동의 없이 보낼 수 있지만, 할인·이벤트를 섞는 순간 광고성 정보가 됩니다. 정보통신망법상 사전 동의가 필요합니다. 안내 문자에 홍보 문구를 넣지 마십시오.

**셋째, 자동 확정입니다.** 위에서 말한 그대로입니다. 확정은 사람이 누르게 만드십시오. 승인 링크 한 번이면 충분합니다.

**넷째, 실패했을 때의 경로입니다.** 문자 발송이 실패하거나, 폼이 열리지 않거나, 알림이 오지 않는 날이 반드시 있습니다. 그때 고객이 다시 전화할 수 있게 **매장 번호를 문자 안에 넣어 두십시오.** 자동화의 마지막 안전장치는 사람이 받는 전화입니다.
