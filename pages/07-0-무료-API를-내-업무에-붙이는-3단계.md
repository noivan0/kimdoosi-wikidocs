### 언제 채팅창을 떠나 API로 가야 하는가

채팅창에 붙여 넣는 방식은 하루 두세 번이면 충분합니다. 그런데 같은 요청을 하루에 열 번 넘게 하거나, 파일 100개를 같은 형식으로 바꿔야 한다면 손이 먼저 지칩니다. 그때가 API로 넘어갈 시점입니다.

API는 어렵지 않습니다. 채팅창에서 하던 일을 프로그램이 대신 요청하는 것뿐이고, 바꿔야 하는 것은 세 가지입니다. 주소, 키, 모델 이름. 나머지는 채팅창에 쓰던 지시문 그대로입니다.

### 엑사원 사례로 보는 구조

2026년 11월 기준으로 LG AI연구원의 엑사원 API를 예로 듭니다. 모델 문서에 공개된 값은 이렇습니다.

| 항목 | 값 |
| --- | --- |
| 모델 ID | k-exaone_v2.5 |
| 주소 | https://api.exaone.ai/v1/chat/completions |
| 호환성 | OpenAI 호환 API |
| 컨텍스트 | 524,288 토큰 (입력 토큰과 max_tokens의 합) |
| 언어 | 한국어와 영어, 텍스트 전용 |
| 비용 | 2026년 11월 20일 확인 시점에 무료. 종료일과 유료 요금은 미공개 |

OpenAI 호환이라는 말은, 지금 쓰는 코드에서 주소와 키와 모델 이름만 바꾸면 그대로 호출된다는 뜻입니다. 이 세 가지가 설정값으로 분리되어 있으면 도구를 바꾸는 데 5분이면 됩니다. 그래서 아래 3단계의 첫 단계가 코드 정리입니다.

### 첫 호출, 세 가지 방법

키는 서비스 문서의 안내에 따라 발급합니다. 발급 화면에서 한 번만 보이는 경우가 많으니 바로 복사해 두십시오.

#### curl

```bash
export EXAONE_API_KEY='발급받은_키'

curl https://api.exaone.ai/v1/chat/completions \
  -H "Authorization: Bearer $EXAONE_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "k-exaone_v2.5",
    "max_tokens": 512,
    "messages": [
      {"role": "user", "content": "한국어로 3문장 요약 연습을 해줘."}
    ],
    "reasoning_effort": "low"
  }'
```

#### 파이썬 requests

```python
import os
import requests

url = "https://api.exaone.ai/v1/chat/completions"
headers = {
    "Authorization": f"Bearer {os.environ['EXAONE_API_KEY']}",
    "Content-Type": "application/json",
}
payload = {
    "model": "k-exaone_v2.5",
    "max_tokens": 512,
    "messages": [{"role": "user", "content": "한국어로 짧게 인사해 주세요."}],
    "reasoning_effort": "low",
    "stream": False,
}
r = requests.post(url, headers=headers, json=payload, timeout=120)
data = r.json()
print(data["choices"][0]["message"]["content"].strip())
print(data["usage"])
```

#### OpenAI SDK

```python
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ["EXAONE_API_KEY"], base_url="https://api.exaone.ai/v1")
r = client.chat.completions.create(
    model="k-exaone_v2.5",
    messages=[{"role": "user", "content": "한국어로 짧게 인사해 주세요."}],
    max_tokens=512,
    reasoning_effort="low",
)
print(r.choices[0].message.content.strip())
```

### 처음에 걸리는 함정 세 가지

#### 응답이 빈 문자열로 옵니다

max_tokens에 추론 토큰이 포함되는 모델이 있습니다. 엑사원 2.5가 그렇습니다. max_tokens를 64처럼 작게 잡으면 추론만 하다가 끝나서 content가 빈 문자열로 돌아옵니다. 512부터 시작해서 늘리거나 줄이십시오. 낮은 값에서 빈 응답이 오면 코드가 틀린 것이 아니라 한도가 작은 것입니다.

응답 앞에 줄바꿈이 붙는 경우도 있어서 content를 읽을 때는 앞뒤 공백을 제거하는 처리를 넣는 편이 안전합니다.

#### 429가 납니다

호출 한도를 넘으면 429가 돌아옵니다. 응답 헤더에 초당, 분당, 일당 한도와 남은 값이 들어 있으니 그것을 읽어 재시도 간격을 정하십시오. 문서에 예시로 적힌 숫자는 계정마다 다를 수 있으므로 내 한도로 읽지 마십시오.

프로그램에서는 이렇게 처리합니다.

- 429를 받으면 최소 몇 초 쉬고 재시도한다
- 재시도 횟수를 3회로 고정하고, 넘으면 로그를 남기고 멈춘다
- 같은 요청을 무한히 반복하지 않는다

#### 컨텍스트가 넘칩니다

입력 토큰과 max_tokens의 합이 컨텍스트를 넘으면 400이 납니다. 긴 문서를 넣을 때는 max_tokens를 함께 줄여 잡으십시오. 문서를 자르는 기준을 정해 두면 이 오류가 거의 사라집니다.

### 붙이기 전에 확인할 조건

무료로 공개된 API에는 대개 조건이 붙습니다. 엑사원의 경우 약관과 문서에서 확인한 것은 이렇습니다.

- 비상업 목적만. 약관이 비상업적 이용 권한을 주고, 모델이나 결과물을 영리 목적으로 이용하는 것과 내 제품에 연동해 제3자가 모델을 호출하게 하는 것을 금지합니다. 사업에 붙이기 전에는 운영사에 물어보고 답을 남겨 두십시오.
- 키 유효기간. 발급일부터 30일인 경우가 있습니다. 만료 전에 새 키를 발급해 환경변수만 바꾸면 되니, 만료일을 캘린더에 걸어 두십시오.
- 학습 이용 동의 여부. 입력값과 결과물을 모델 학습에 쓰는 것이 선택 동의인 서비스가 있습니다. 동의하지 않으면 요청 처리에만 쓰고 저장하지 않는다고 적혀 있어도, 동의 상태를 직접 확인하고 정하십시오.
- 개인정보. 타인의 개인정보가 들어간 입력값을 넣지 말라는 조항이 흔합니다. 고객 문의 원문, 주민번호, 연락처가 섞인 문서는 가린 뒤 넣으십시오.

무료라는 말의 범위도 함께 읽으십시오. 종료일이 공개되지 않은 무료는 언제 끝날지 모르는 무료입니다. 업무에 붙일 때는 호출부를 한 파일에 모으고 모델 이름과 주소를 설정값으로 빼 두십시오. 조건이 바뀌면 한 곳만 고치면 됩니다.

### 내 업무에 붙이는 3단계

| 단계 | 하는 일 | 끝났다는 신호 |
| --- | --- | --- |
| 1 | 호출 코드를 한 파일에 모으고, 지시문은 바깥 파일로 분리 | 지시문을 고칠 때 코드를 열지 않는다 |
| 2 | 모델 이름, 주소, 키를 설정값으로 분리 | 도구를 바꿀 때 설정만 고친다 |
| 3 | 실패를 먼저 정한다: 타임아웃, 429, 빈 응답, 길이 초과 | 네 경우에 프로그램이 멈추거나 재시도한다 |

3단계를 건너뛰면 처음 며칠은 잘 돌다가, 한도에 걸린 날 조용히 빈 결과를 냅니다. 자동화에서 가장 위험한 실패는 멈추는 실패가 아니라 빈 결과를 정상처럼 내놓는 실패입니다.
