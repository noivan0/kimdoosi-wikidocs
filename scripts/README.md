# 원고 추가 가이드

이 저장소는 위키독스 깃허브 연동 책의 원고입니다. 위키독스는 `TOC.md` 와 `pages/` 를 읽어 책을 구성하고, `push` 를 감지해 자동으로 반영합니다.

## 구조

```
README.md      책 제목과 소개 (첫 줄 # 제목이 책 제목이 된다)
TOC.md         목차. - [제목](pages/파일.md), 하위는 2칸 들여쓰기
pages/         각 장의 원고
assets/        이미지
scripts/       린트와 장 추가 도구
```

## 새 장 추가

1. 원고를 마크다운으로 쓴다. 본문은 `###` 부터 시작하고 이모지와 수평선(`---`)은 쓰지 않는다.
2. 아래 명령으로 페이지 생성, 목차 갱신, 린트, 커밋, 푸시를 한 번에 한다.

```bash
python3 scripts/add_chapter.py --title "09. 새 장 제목" --file drafts/new.md
python3 scripts/add_chapter.py --title "09-1. 하위 장" --file drafts/new.md --parent "09"
python3 scripts/add_chapter.py --title "09. 새 장 제목" --file drafts/new.md --no-push
```

3. 위키독스에서 반영을 확인한다. 늦으면 책 수정 > 깃허브 탭에서 `지금 동기화`.

## 린트

```bash
python3 scripts/wikidocs_lint.py
```

검사 항목: 이모지, 수평선, 본문 H1/H2, 목록 앞 빈 줄, 중첩 목록 4칸, 이스케이프 안 된 `$`, 화살표 특수기호, TOC 와 파일 불일치, TOC 제목과 본문 첫 제목 중복.

## 위키독스 마크다운 규칙 요약

- 본문에 `#`(H1) 금지. 페이지 제목이 자동 출력된다.
- `##`(H2)는 자제. PDF 변환 시 H2 마다 강제 페이지 나눔이 생긴다. `###` 부터 쓴다.
- 이모지 금지. PDF 변환 오류와 기기별 깨짐의 원인이다.
- 수평선(`---`, `***`, `___`) 금지. 표 구분자와 충돌한다.
- 목록 앞에는 반드시 빈 줄 한 줄.
- 중첩 목록은 스페이스 4칸.
- 본문의 `$` 는 `\$` 로 이스케이프. 코드 블록 안은 그대로.
- 화살표는 `->` 로 쓴다. `→` 같은 특수기호는 PDF 에서 깨진다.
- 페이지 간 내부 링크(`다른페이지.md`)는 깨진다. 외부 링크만 쓴다.
- 팁 박스는 `[[TIP("제목")]]` ... `[[/TIP]]` 형식. 인식되는 키워드는 TIP 뿐이다.
- 같은 단계의 목차는 제목 알파벳순으로 정렬되므로 `01`, `02` 번호를 붙인다.

## 발행 회차와 연동

인스타 자율발행 회차가 끝나면 그 회차의 실전 팩(`*_dm_packs/*.md`)을 원고로 다듬어 다음 번호로 추가한다. 팩에는 프롬프트 원문과 판정 기준이 이미 있으므로, 도입부 한 단락과 마무리 링크만 붙이면 한 장이 된다.

## 주의

- 개인정보, 실명, 연락처, 주소, 계정 정보, 내부 시스템 이름을 넣지 않는다.
- 확인되지 않은 수치를 측정값처럼 쓰지 않는다. 목표 시간이면 목표라고 적는다.
- 외부 서비스의 요금과 조건은 확인 날짜를 함께 적는다.
